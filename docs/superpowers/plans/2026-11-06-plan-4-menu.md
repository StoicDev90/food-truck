# Plan 4: Menú público Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** El cliente escanea el QR y en `/` ve, en el celular y en segundos, el menú de Oasis Itaipu: estado abierto/cerrado, pestañas por categoría, productos con foto, precio en ₲ y "AGOTADO", y un pie con horario, mapa, WhatsApp e Instagram.

**Architecture:** La página `/` es estática y cacheada: una función `'use cache'` con `cacheTag(TAG_MENU)` lee categorías, productos visibles y configuración con un cliente Supabase anónimo sin cookies (RLS anon ya filtra `visible and activo` y no deja leer el costo). Las acciones de Planes 2–3 ya llaman `updateTag(TAG_MENU)` al vender, anular, mover stock o editar catálogo/configuración. Lo que depende de la hora (abierto/cerrado) se calcula en el navegador desde los horarios, para que la caché nunca muestre un estado viejo. Lógica pura en `lib/menu/*.ts`; componentes en `components/menu/`.

**Tech Stack:** Next.js 16.4.5 (`cacheComponents: true`, `'use cache'`, `cacheTag`), React 19, Tailwind 4 + shadcn/ui, Supabase (anon), Vitest + RTL.

**Spec:** `docs/specs/2026-11-06-food-truck-sistema-design.md` (§7: el menú muestra solo ₲; §8 menú público; §12 `controla_stock`) y `docs/specs/2026-11-06-identidad-visual-design.md` (§7 tokens, §8 tipografía, §9 temas, §10 menú, §13 accesibilidad). Si este plan y una spec chocan, manda la spec.

## Global Constraints

- Stack fijado: Next.js 16.4.5, Tailwind + shadcn/ui, Supabase, Vitest + RTL. `cacheComponents: true` sigue activo.
- **El menú no usa cookies ni sesión**: nada de `crearClienteServidor` (que hace `await connection()` y volvería dinámica la página). Cliente anónimo `createClient(url, anonKey, { auth: { persistSession: false, autoRefreshToken: false } })` solo dentro de la función cacheada.
- Datos: `productos` con columnas explícitas (`id, categoria_id, nombre, descripcion, foto_path, precio_gs, stock, controla_stock`), nunca `select('*')` ni `costo_gs`. Anon ya ve solo `visible and activo`.
- **Agotado** = `controla_stock && stock <= 0`. Con `controla_stock = false` nunca figura agotado (spec §12). Agotado no se oculta: se muestra en gris con "AGOTADO".
- Solo ₲, formato `₲ 8.000` (`formatoGs` de lib/pos/formato.ts). Nada de R$ en el menú (spec §7).
- "Día" y horarios en `America/Asuncion` (UTC−3 fijo). Horario con `cierra <= abre` = cierra después de medianoche (del día siguiente). `null` = cerrado ese día. La fila puede tener `horarios = {}` (sin cargar).
- Reusar: `Horarios`/`DIAS`/`validarHorarios` (lib/admin/horarios.ts), `urlImagen` (lib/imagenes.ts), `Sticker`/`Palmera` (components/marca), `BotonTema` (clave `tema-menu` sale sola por el pathname), `TAG_MENU` (lib/cache.ts).
- Colores solo por tokens (identidad §7.1; `text-precio`, `text-marca`, `bg-primary`…), nunca hex. Contraste ≥ 4.5:1 en ambos temas. Fredoka para títulos y precios, Nunito para el resto.
- Objetivos táctiles ≥ 44 × 44 px; foco visible; `aria-label` en español en botones de solo ícono; Lucide; estado nunca solo por color ("AGOTADO", "Abierto", "Cerrado" en texto). Animaciones ≤ 200 ms y nada si `prefers-reduced-motion`.
- shadcn `Button` es base-ui con `type="button"` por defecto: en formularios siempre `type="submit"` (lección del Plan 3).
- Commits: paths explícitos; nunca `.claude/`, `.agents/`, `.superpowers/`, `CLAUDE.md`, `AGENTS.md`, `skills-lock.json`, `docs/design/fotos/`, `.env.local`.
- Gate de cada tarea (una vez, tras la última ronda de arreglos): `npm test && npm run test:db && npm run typecheck && npm run lint && npm run build`.

## Review Focus

1. **Horario que pasa la medianoche**: viernes 18:00–02:00, el sábado 01:00 hora de Asunción → "Abierto · cierra 02:00"; el sábado 02:30 → "Cerrado" (o la próxima apertura). → test en Task 1.
2. **Horarios sin cargar o corruptos** (`{}`, `null`, un día con "25:00") → píldora "Cerrado" y pie "Horario no disponible"; nunca un crash. → test en Task 1 y Task 2.
3. **Producto con `controla_stock = false` y stock 0** → se ve normal, sin "AGOTADO". → test en Task 1.
4. **Categoría sin productos visibles** → no tiene pestaña ni sección. → test en Task 1.
5. **Sin WhatsApp / Instagram / ubicación cargados** → esos botones no aparecen (ningún enlace roto `https://wa.me/`). → test en Task 2.

- Produces:
  - `crearClientePublico(): SupabaseClient<Database>` (anon key, sin sesión; sin `'server-only'` para poder usarlo en tests de base).
  - `type ProductoMenu = { id: string; nombre: string; descripcion: string | null; fotoUrl: string | null; precioGs: number; agotado: boolean }`
  - `type SeccionMenu = { id: string; nombre: string; productos: ProductoMenu[] }`
  - `type DatosMenu = { nombre: string; logoUrl: string | null; horarios: Horarios | null; whatsapp: string | null; instagram: string | null; ubicacion: string | null; secciones: SeccionMenu[] }`
  - `armarMenu(e: { categorias: { id: string; nombre: string; orden: number }[]; productos: { id: string; categoria_id: string; nombre: string; descripcion: string | null; foto_path: string | null; precio_gs: number; stock: number; controla_stock: boolean }[]; config: { nombre: string; logo_path: string | null; horarios: unknown; whatsapp: string | null; instagram: string | null; ubicacion: string | null } | null }): DatosMenu` — secciones por `orden` y luego `nombre`; productos por `nombre` (`localeCompare` 'es'); categorías sin productos se omiten; `horarios` pasa por `validarHorarios` (inválido → `null`); `config` null → nombre "Oasis Itaipu" y el resto null.
  - `cargarMenu(): Promise<DatosMenu>` en `lib/menu/datos.ts`: `'use cache'`, `cacheTag(TAG_MENU)`, `cacheLife('hours')`; lee con `crearClientePublico()`; error de Supabase → lanza (no cachea un menú vacío como si fuera real).
  - `type EstadoNegocio = { abierto: true; cierra: string } | { abierto: false; abre: { dia: (typeof DIAS)[number]; hora: string } | null }`
  - `estadoNegocio(horarios: Horarios | null, ahora: Date): EstadoNegocio` — usa la hora de Asunción; un horario que pasa la medianoche cuenta como abierto hasta `cierra` del día siguiente; `abre` = próxima apertura dentro de 7 días o `null`.
  - `filasHorario(horarios: Horarios | null): { dia: string; texto: string }[]` — 7 filas "Lunes"…"Domingo" con "18:00 – 23:00" o "Cerrado"; `null` → `[]`.

- `EncabezadoMenu` (cliente): arriba, `Sticker` ~130 px centrado sobre degradé radial suave, `EstadoAbierto` y `BotonTema` arriba a la derecha. Al pasar un umbral de scroll (sentinela con `IntersectionObserver`), queda fija una barra con `Palmera` + nombre + `BotonTema` y debajo las pestañas. Transición ≤ 200 ms; sin animación con `prefers-reduced-motion`.
- `PestanasMenu` (cliente): `<nav aria-label="Categorías">` con enlaces a `#cat-<id>` en forma de píldora; scroll suave (no con reduced-motion); scroll-spy (`IntersectionObserver`) marca la activa con `aria-current="true"`; activa = relleno `bg-primary text-primary-foreground` en noche y `bg-secondary text-secondary-foreground` en claro (tokens).
- `ItemProducto`: foto cuadrada 72 px, esquinas 18 px (`next/image` `unoptimized`, `loading="lazy"`, `alt` = nombre); sin foto → `Palmera` sobre fondo suave. Nombre Nunito 800, descripción con opacidad ~0.75, precio Fredoka `text-precio` (`formatoGs`). Agotado: foto/placeholder en escala de grises, textos atenuados y etiqueta "AGOTADO" de alto contraste.
- `PieMenu`: `filasHorario` (o "Horario no disponible" si está vacío); "Cómo llegar" → `ubicacion` (abre en pestaña nueva, `rel="noopener noreferrer"`); botones de ancho completo "WhatsApp" → `https://wa.me/<whatsapp>` e "Instagram" → `https://instagram.com/<instagram>`; cada botón se omite si su dato es `null`. Sin `iframe` de mapa **[call de Claude: evita terceros y CSP; el enlace abre el mapa del dueño]**.
- Menú vacío (sin secciones): mensaje "Pronto vas a ver el menú acá." en vez de pestañas vacías.
