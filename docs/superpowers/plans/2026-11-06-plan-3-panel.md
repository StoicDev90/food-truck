# Plan 3: Panel de dueños Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Los dueños manejan todo desde `/admin`: productos, categorías, fotos, stock, empleados, cotización del real, datos del negocio, turnos (cierre forzado y corrección de conteo), movimientos de caja y reportes, con la pantalla "Hoy" como inicio.

**Architecture:** La base del Plan 1 ya trae las escrituras transaccionales (`ajustar_stock`, `corregir_conteo`, `cerrar_turno` forzado, `fijar_cotizacion_manual`, …) y RLS de dueño para leer todo. Este plan agrega una migración con funciones de reporte agregadas en SQL (`reporte_*`, solo dueños) y el bucket de imágenes, una capa server por sección (`lib/admin/<seccion>.ts` con Server Actions; lecturas en la página) y componentes cliente en `components/admin/`. Empleados usa service role (Auth admin) solo en el servidor. La cotización oficial del BCP (BRL→PYG) la trae un Vercel Cron a las 00:05 vía la API de AllRatesToday.

**Tech Stack:** Next.js 16.4.5 (App Router, Server Actions, `cacheComponents: true`), React 19, Tailwind 4 + shadcn/ui (`base-nova`), Supabase (Postgres, Auth admin, Storage), Vitest + React Testing Library.

**Spec:** `docs/specs/2026-11-06-food-truck-sistema-design.md` (§7 cotización, §9 usuarios, §10.1/§10.5/§10.7 turnos y caja, §11 panel, §12–§13 datos) y `docs/specs/2026-11-06-identidad-visual-design.md` (§7 tokens, §9 temas, §12 panel, §13 accesibilidad). Si este plan y una spec chocan, manda la spec.

## Global Constraints

- Stack fijado: Next.js 16.4.5, Tailwind + shadcn/ui, Supabase, Vitest + RTL. `cacheComponents: true` sigue activo: lo que lea `cookies()`/`searchParams` va dentro del `<Suspense>` del layout protegido (ya hace `await connection()`).
- **Toda página bajo `app/admin/(protegido)/` y toda Server Action del panel llama a `requerirAcceso('admin')` por su cuenta** (el layout solo no alcanza). Excepción ya existente: reusar acciones del POS (`registrarMovimientoCaja`) que exigen `'pos'` + dueño.
- Patrón de Server Action (igual que `lib/pos/acciones.ts`): `try { await requerirAcceso('admin'); validar → VALOR_INVALIDO; llamar } catch (e) { unstable_rethrow(e); fallo(null) }`. Nunca lanzan; devuelven `Resultado<T>`.
- **`productos` siempre con lista explícita de columnas**, nunca `select('*')`. El costo se lee solo con `rpc('costos_productos')`.
- Service role (`crearClienteAdmin`) **solo** para Auth admin de empleados, `intentos_login` y el cron. Todo lo demás con el cliente de sesión (`crearClienteServidor`) para que RLS y `es_dueno()` apliquen.
- PIN de empleado: contraseña de Supabase = `passwordEmpleado(usuario, pin)` de `lib/auth/pin.ts`; nunca el PIN crudo. Resetear PIN también borra el contador `intentos_login` de esa cuenta (`claveCuentaEmpleado(usuario)`).
- Tras toda escritura que cambie lo que ve el menú público (productos, categorías, stock, configuración): `updateTag(TAG_MENU)`.
- Errores: códigos de `lib/errores.ts` → `MENSAJES_ERROR[codigo]`; sin código → "No se pudo completar. Probá de nuevo."
- ₲ enteros, formato `₲ 31.000` (`formatoGs`); R$ 2 decimales `R$ 21,38` (`formatoBrl`); inputs con `parseMontoGs`/`parseMontoBrl`. "Día" = `America/Asuncion`; **un turno y todas sus ventas pertenecen al día en que se abrió** (spec §10.1, §11.3).
- Colores solo por tokens (identidad §7.1), nunca hex en componentes. Contraste ≥ 4.5:1; texto sobre el fondo de página usa `text-exito-texto` / `text-aviso-texto` / `text-destructive-texto`. Menú lateral siempre oscuro.
- Fuentes Fredoka (títulos, montos) y Nunito (resto). Foco visible; objetivos ≥ 44 × 44 px; botones de solo ícono con `aria-label` en español; íconos Lucide; estado nunca solo por color.
- Formularios: el botón de enviar se bloquea al primer clic (lock con `useRef`, no solo `disabled`) y muestra "Guardando…" hasta la respuesta (hook `useEnvio`, Task 1).
- Tipos: tras cada migración, `npm run db:types` y commitear `types/supabase.ts`.
- Commits: paths explícitos; nunca `.claude/`, `.agents/`, `.superpowers/`, `CLAUDE.md`, `AGENTS.md`, `skills-lock.json`, `docs/design/fotos/`, `.env.local`.
- Gate de cada tarea (una vez, tras la última ronda de arreglos): `npm test && npm run test:db && npm run typecheck && npm run lint && npm run build`.

## Review Focus

1. **Turno que pasa la medianoche**: una venta a las 00:30 de un turno abierto a las 23:30 cuenta en el día de apertura en todos los reportes, y la suma de "Ventas" de un día coincide con el "Cierre diario". → test en Task 2.
2. **Montos con separador de miles** ("8.000", "₲ 15.500") en precio, costo y cotización → se guardan 8000 / 15500, no 8; basura ("8,5" en ₲, "abc") se rechaza antes del servidor. → test en Task 3 y Task 6.
3. **Borrar una categoría con productos** → mensaje "La categoría tiene productos. Movelos antes de borrarla.", no un error genérico ni un crash. → test en Task 3.
4. **La API de cotización falla, tarda, responde 403/429 o devuelve basura** → el cron responde 502, no escribe nada y el POS sigue bloqueando Efectivo R$; un valor fuera de [500, 5000], `derived: true` o `rate_date` de más de 5 días cuenta como basura. → test en Task 6.
5. **Doble clic en "Crear empleado" / "Cerrar turno forzado"** → un solo empleado / un solo cierre. → test en Task 5 y Task 8.
